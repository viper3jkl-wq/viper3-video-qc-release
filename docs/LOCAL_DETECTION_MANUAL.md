# Viper3 本地检测手册

适用版本：**Viper3 v2.4**

应用入口：仓库根目录的 `index.html`

版本变化：参见 [完整更新日志](../CHANGELOG.md)

本手册用于在本机完成画面异常检测、交付与音频验收、字幕校对、文稿匹配、转码导出和报告归档。自动结果用于初检与定位，最终交付仍需结合原片、配音、剪辑软件和目标平台人工复核。

## 1. 使用前须知

### 1.1 本地与只读原则

- 核心检测、转码、字幕校对和 NCM 转换均在浏览器本地运行，不主动上传素材。
- 原始视频、音频和字幕不会因导入或检测而被覆盖。
- SRT 的“采用建议”只改变网页中的校对状态；只有下载修正版后才会生成新文件。
- “清理字幕 / 视频 / 列表”只移除网页中的数据，不删除本机原文件。
- 历史报告保存在当前浏览器。清理站点数据、使用其他浏览器或更换设备后，历史可能不可见，应及时导出需要长期保存的报告和项目配置。

### 1.2 运行环境

| 项目 | 要求 |
|---|---|
| 推荐浏览器 | 最新版 Microsoft Edge 或 Google Chrome |
| 核心功能 | JavaScript、WebCodecs、本地文件读取权限 |
| 推荐测试素材 | 浏览器可解码的 H.264 / MP4；其他格式以实际解码能力为准 |
| 可选 Whisper | Python 3、首次安装依赖所需的网络、本地模型文件 |
| 批量重命名 | 支持 File System Access API 的浏览器，以及目标文件夹的读写授权 |

H.265 依赖系统解码器；Windows 未安装 HEVC 扩展时可能无法解码。ProRes、MPEG-2 等浏览器不支持的编码需要先转码，不能把“无法解码”当作“检测通过”。

### 1.3 启动应用

1. 在公开发布仓库选择 **Code → Download ZIP**，或克隆发布仓库。
2. 解压后，用 Edge 或 Chrome 打开根目录的 `index.html`，即可进入工作区。
3. 确认侧栏页脚显示 **v2.4**。
4. 先用一段已知结果的短视频或字幕完成试跑，再执行大批量任务。

核心功能不需要安装 Node.js、Python 或数据库。只有主动使用 Whisper 文稿匹配时，才需要启动本机识别服务。

### 1.4 发布文件校验

发布库的 `release-manifest.json` 提供 `index.html` 的字节数与 SHA-256，可用于核对下载文件是否与发布记录一致。

Windows 可在发布目录执行以下命令，并将输出与清单中的 `sha256` 对比：

```powershell
(Get-FileHash -Algorithm SHA256 .\index.html).Hash.ToLower()
```

## 2. 推荐检测流程

1. **备份并确认素材**：原片、字幕、人声、音乐、音效和输出目录分开存放。
2. **画面初检**：检测黑帧、疑似夹帧和 PTS 连续性丢帧。
3. **逐帧复核**：核对异常点前后画面，排除蒙太奇、片尾淡出等艺术处理。
4. **交付与音频验收**：检查平台规格、响度、真峰、静音、声道和首尾黑场。
5. **字幕校对**：检查文本、标点、大小写、时间轴和画框；需要时进行文稿匹配。
6. **转码与交付导出**：先单组试导出，再批量生成五类交付版本。
7. **终检与归档**：在目标播放器或剪辑软件中复核，导出报告和项目配置。

## 3. 画面异常检测

### 3.1 导入视频

1. 打开「画面检测」。
2. 点击「添加视频」或「导入文件夹」，也可以拖放文件。
3. 在检测队列中勾选本次需要检测的文件。
4. 可按文件名称或拖入时间排序，并切换升序 / 降序。
5. 点击队列中的文件，确认预览能正常显示画面。

支持导入 MP4、MOV、MKV、WebM、TS 等容器，以及浏览器可解码的 H.264、H.265、AV1、VP9、VP8 等编码。能导入不等于能解码，必须确认预览和检测均能运行。

### 3.2 选择检测预设

| 预设 | 建议用途 | 复核重点 |
|---|---|---|
| 严格 | 已知问题回归、交付前复检、尽量降低漏检 | 误报可能增加，需逐条看前后帧 |
| 均衡 | 常规成片首次检测 | 兼顾漏检与误报，仍不能代替人工终审 |
| 宽松 | 快速蒙太奇较多、初检误报过多的素材 | 可能减少短异常检出，不能用于替代严格复检 |

修改任何滑块后，预设选中状态会取消，表示正在使用自定义参数。不要为了让结果“变少”而直接切宽松；先确认异常是否真实存在。

### 3.3 主要参数

| 参数 | 含义与调整建议 |
|---|---|
| 像素亮度阈值 | 判定暗像素的亮度上限。暗部较多的影片不宜盲目调高 |
| 暗像素占比 | 一帧中暗像素达到该比例才进入黑帧判断 |
| 最短持续时长 | 过滤极短黑场；调低更敏感，调高会减少短黑场报告 |
| 画面突变阈值 | 控制场景变化强度。漏检时可小幅降低，误报多时可小幅提高 |
| 最长异常片段 | 需要检查的短段长度，范围为 1–6 帧，应覆盖目标夹帧长度 |
| 分析帧率 | 默认自动读取；只有确认容器信息异常时才手动指定为原片真实帧率 |

当前版本保留“前后回归阈值”控件，但现行判据 C 使用固定系数，该控件不参与最新判定。需要影响短段夹帧时，应调整画面突变阈值、最长异常片段或检测预设，并用已知样本回归。

### 3.4 开始与恢复检测

1. 至少开启「黑帧检测」或「夹帧检测」之一。
2. 按需选择平台规格模板，并确认是否开启「音频体检」。
3. 点击「开始检测」，观察当前文件、扫描时间码和进度。
4. 播放、暂停预览不会改变后台独立检测过程。
5. 需要中止时点击「停止」。重新添加相同文件后，可按提示跳过已完成部分；如需全量重扫，先丢弃旧进度。
6. 大批量任务建议分批执行，避免内存不足或浏览器长时间高负载。

PTS 丢帧检测会根据相邻帧时间戳的异常间隔生成“丢帧”结果，可在结果类型中单独筛选。可变帧率、非常规 TS 封装或异常容器时间戳需要结合原始文件进一步判断。

### 3.5 逐帧复核结果

1. 在「检测结果」中按黑帧、夹帧或丢帧筛选。
2. 点击问题类型标签或开始时间码，定位对应画面。
3. 使用「上一帧 / 下一帧」或键盘 `←` / `→`，检查异常点前后至少数帧。
4. 对照开始 / 结束时间码、帧范围、持续时长、置信度和源文件。
5. 在剪辑软件中以相同帧率打开原片，确认时间码和画面一致。

结果解释：

- **黑帧**：满足亮度、暗像素比例和持续时长的区段。片头、片尾和淡出黑场也可能是正常创作，不应直接判为制作错误。
- **疑似夹帧**：短段异常或镜头边界突变候选。快速蒙太奇、闪光和亮度变化需要人工排除。
- **丢帧**：PTS 间隔异常候选，不等同于肉眼可见的画面损坏，需检查封装和时间轴。

调参后必须用包含已知黑帧、1–3 帧夹帧、快速蒙太奇和片尾淡出的样本复测，不能只看单一视频的结果数量。

## 4. 交付规格与音频体检

### 4.1 开启验收

1. 在「画面检测 → 检测参数 → 交付验收」中选择目标平台模板。
2. 不需要平台规格时选择“不检查”，仍可单独开启音频体检。
3. 开始画面检测，完成后切换到「交付验收」。
4. 逐项查看“通过 / 注意 / 不通过”、实测值和模板要求。

验收内容包括分辨率、画幅比例、帧率、码率、时长、编码、音轨，以及首尾黑场。音频检查包括 BS.1770 响度、真峰、静音段、左右声道相关性和短时响度跳变。

### 4.2 交付前必须人工确认

- 模板是否与本次平台要求一致，不要沿用其他项目模板。
- 无声、声道异常或响度告警是否来自源文件、转码或封装。
- MP4 在 Finder、QuickTime、系统播放器或目标平台中是否有声。
- 首尾黑场是否为平台允许的创意内容。
- 检测结果不能代替完整试听、真峰监测设备或平台实际上传验证。

## 5. SRT 字幕校对

### 5.1 导入与检查

1. 打开「SRT 字幕校对」。
2. 导入一个或多个 SRT；也支持 TTML 导入后归一化。
3. 支持 UTF-8、UTF-16 和 GB18030，乱码时先确认源文件编码。
4. 需要画面对照时，导入对应视频并选择横屏或竖屏比例。
5. 点击「开始校对」，按状态、严重级别和问题类型筛选结果。

检查范围包括英文大小写、拼写、空格、断句、缩写断行、行数、专名、时间轴、中英文标点和英文台词中文夹杂。自动建议不等于语境终审。

### 5.2 采用建议与人工复核

1. 点击字幕块或问题项，先阅读完整原文。
2. 核对修改建议及上下文，再选择单条或批量采用。
3. 采用后，在「原文」下方检查绿色区域的**完整采纳后字幕**。
4. 页面预览与修正版导出使用同一套修改逻辑；仍需检查多规则同时采用后的整句。
5. 误报可标记忽略，已人工确认的项目使用对应状态，便于后续筛选。

特别注意：

- 英文使用半角标点，中文使用中文标点。
- 句末标点建议与首字母大小写检查相互独立。
- 小写跨字幕续句和省略号不应被强行补句号。
- `?!`、`!?` 及全角组合按规则只保留一个问号。
- 句首 `!`、`！”` 等残留可整体清理，但纯标点字幕不能被删成空字幕。
- 英文字幕中的多余中文可按建议删除；正常中文字幕中的英文名称或单词不触发该规则。
- 整张中文字幕被采纳移除后，修正版会跳过该空白字幕并重新编号；预览区会明确提示该字幕将被移除。
- 发音、语速、配音错漏和新音频时间轴不能仅凭 SRT 判定。

### 5.3 导出字幕与报告

- 「下载当前修正版」：只导出当前字幕的新文件。
- 「批量修正版 ZIP」：导出多份修正版，原文件保持不变。
- 「导出校对报告」：支持 HTML、CSV、XLSX、JSON，可按当前、多选或全部字幕导出，并可独立选择全部问题、仅错误或仅警告；汇总、明细和处理状态随级别筛选同步。
- 「转换字幕格式」：支持 SCC、SRT、TTML 的当前文件或批量转换。

SCC 导出前应确认视频帧率、丢帧 / 非丢帧和 Pop-on / Roll-up / Paint-on 设置。SCC 文件格式校验通过不代表达芬奇内部显示已验收；必须实机检查起止时间码、多行字幕和短字幕密集段的装载节奏。

## 6. 可选：Whisper 文稿匹配

不使用该功能时，无需下载模型或启动服务。

1. 打开「SRT 字幕校对 → 文稿匹配」。
2. 点击「下载本地识别服务」并解压。
3. macOS 运行 `启动本地识别.command`；Windows 运行 `start-windows.bat`。
4. 首次启动会创建 `.venv` 并安装依赖，需要 Python 3 和网络。
5. 回到页面点击「检测本地服务」，按需下载或导入 small / large-v3 模型。
6. 导入音视频和 TXT 文稿，或直接在文本框粘贴文稿。
7. 明确选择模型后点击「开始匹配」。模型默认不加载，不会在打开页面时自动识别。
8. 检查逐句对齐、时间码、文本和置信度，再导出 SRT、SCC、TTML、TXT、双语 SRT 或 XLSX。

本地模型目录至少应包含有效的 `model.bin` 和 `config.json`。服务只监听 `127.0.0.1:8765`；端口被占用、依赖安装失败或模型不完整时，应先解决对应问题，不要把离线对齐结果当作真实语音识别结果。

## 7. 视频转码与五类交付导出

### 7.1 视频转码

1. 打开「视频转码」，导入待处理视频。
2. 选择编码、容器、分辨率、码率、快速模式和音频设置。
3. 先用短样本检查浏览器是否支持所选编码，以及输出是否能正常播放。
4. 开始转码，完成后复核画面、音轨、时长和文件大小。
5. 需要时继续执行交付规格和音频体检。

支持 H.264、H.265、VP9、AV1，以及 MP4、MOV、WebM、MKV。实际可用组合受浏览器和系统编码能力限制。大批量任务应分批执行，不能只凭“转码完成”判断交付合格。

### 7.2 素材配对与导出

五个素材槽位分别为视频、字幕、人声、音乐和音效。优先按槽位导入对应文件夹，以便利用目录名称识别角色；多选文件时注意检查未识别数量。

1. 打开「交付版本导出」。
2. 分别导入五类素材，检查分组总数、可导出数、待补数和未匹配数。
3. 按名称或拖入时间排序，逐组确认没有跨目录同名音频误配。
4. 先执行「导出当前组」，确认无误后再「导出选中」或「导出全部」。
5. 解压 ZIP，检查中文文件名、目录结构、缺项和重复嵌套。

五类交付目录：

| 目录 | 内容 |
|---|---|
| `01_成片` | 字幕 + 人声 + 音乐 + 音效 |
| `02_无字幕有音乐` | 人声 + 音乐 + 音效，无字幕 |
| `03_字幕无音乐` | 字幕 + 人声，无音乐、无音效 |
| `04_声音分轨` | 人声、音乐、音效独立文件 |
| `05_字幕` | 字幕文件 |

多集导出应共享 01–05 顶层目录，不出现同一集名称的双重嵌套。标准完整配置通常每组生成 3 个视频、3 条分轨和 1 个字幕文件；如更改音频或导出设置，应以实际配置复核数量。

## 8. NCM 格式转换

1. 打开「NCM 格式转换」。
2. 导入有权处理的本地 NCM 文件或文件夹。
3. 按需开启标题、歌手、专辑和封面写入。
4. 点击「开始转换」，确认输出自动识别为 MP3 或 FLAC。
5. 逐个下载结果；少量文件可打包 ZIP，大批量建议逐个下载以降低内存占用。

转换只解除封装，不重新编码、不改变音频流，也不修改原文件。非标准或新版私有封装可能失败，失败时不应生成或交付伪成功文件。

## 9. 报告与项目配置

### 9.1 报告选择

| 场景 | 建议格式 |
|---|---|
| 团队浏览、打印和复核 | HTML / PDF |
| Excel 筛选与统计 | CSV / XLSX |
| 完整参数、事件和结构化归档 | JSON |
| 字幕文本交付 | SRT / SCC / TTML |

画面检测与 SRT 校对历史在「检测报告」中分类显示。版本记录可按日期筛选，用于定位某一天的功能变化；完整历史同时发布在 [CHANGELOG.md](../CHANGELOG.md)。

### 9.2 项目配置

在「检测报告 → 项目配置」导出或导入 JSON，可保存专名库、打码词表、画幅与参考文本框等项目设置。配置不包含原始视频，不能替代检测报告或修正版字幕的备份。

## 10. 交付验收清单

- [ ] 所有目标文件均完成检测，没有“无法解码”或中断文件被误算为通过。
- [ ] 真实帧率、时间码、帧号与剪辑软件一致。
- [ ] 已知夹帧样本仍能命中，快速蒙太奇和纯亮度变化已人工排除。
- [ ] 黑场、丢帧和 PTS 异常均已逐条复核。
- [ ] 平台规格与音频体检无未处理的不通过项。
- [ ] 导出视频在目标播放器中有画面、有声音，音轨和分轨内容正确。
- [ ] 字幕文本、标点、大小写、时间轴和画框已终审。
- [ ] SCC 已在达芬奇或目标交付软件中实机验证。
- [ ] ZIP 可正常解压，无乱码、缺项、重复目录或双重集名嵌套。
- [ ] 检测报告、修正版字幕和项目配置已归档。

## 11. 常见问题排查

| 现象 | 优先检查与处理 |
|---|---|
| 无法解码或检测中断 | 确认浏览器与系统解码器；先转为 H.264 / MP4，再重新检测，不要记为通过 |
| H.265 无法打开 | Windows 检查 HEVC 扩展；改用浏览器支持的编码 |
| FPS 明显异常 | 保持自动分析并核对容器元数据；仅在确认真实帧率时手动指定，再全量重扫 |
| 时间码差一帧 | 核对原片帧率、编辑列表、SCC 丢帧设置及剪辑软件时间线 |
| 蒙太奇误报较多 | 先逐帧确认，再小幅提高突变阈值或使用均衡 / 宽松；保留严格复检 |
| 已知夹帧漏检 | 使用严格预设，小幅降低突变阈值，确认最长异常片段覆盖目标长度 |
| 片尾淡出被报黑帧 | 结合创作意图人工忽略，不要为了消除报告而放宽全部黑帧规则 |
| 大批量内存不足 | 分批检测、关闭重负载页面、逐个下载，避免一次性汇集大型 ZIP |
| Whisper 连接失败 | 检查 Python 3、首次依赖安装、启动脚本和 `127.0.0.1:8765` 是否可用 |
| 模型无法导入 | 检查 `model.bin`、`config.json` 和完整模型文件，不使用 Git LFS 指针代替权重 |
| SCC 显示异常 | 核对帧率、丢帧模式、字符限制和 Pop-on 装载节奏，在达芬奇中复验 |
| 历史报告消失 | 检查是否更换浏览器、设备或清理站点数据；以后及时导出报告与配置 |

## 12. 发布校验与验收说明

公开使用者可核对 `release-manifest.json` 中各文件的字节数和 SHA-256。`index.html` 是唯一完整应用入口。

当前发布版已完成 15 个脚本块语法检查、86 项 SRT 断言、NCM 合成 MP3 / FLAC 往返、200 项 Auto Key 算法断言和 43 项批量重命名断言，并通过 22 项核心浏览器断言与 53 项工具模块浏览器断言。

工具验收使用合成 WAV、OPFS 和模拟采集流。真实后台停止设备音轨仍需在正常浏览器标签页中复核。自动回归不能替代真实视频、真实模型、达芬奇和播放器验收。

## 13. 批量重命名与 Auto Key

### 13.1 批量重命名

1. 先备份重要文件，打开「批量重命名」，点击「选择文件夹并授权」。应用只枚举当前文件夹，不递归处理子文件夹。
2. 选择替换文本、前缀 / 后缀、修改扩展名、序号重命名或全部重新重命名，再点击「生成预览」。查找文本为空时不会改名；替换为留空表示删除匹配文字。
3. 逐项核对原名、新名和冲突原因。存在任何冲突时，「执行真实改名」保持禁用。
4. 确认执行后，应用通过临时名进行两阶段原生移动，可处理链式改名、交换文件名和仅修改大小写；失败时进行回退检查，但仍应核对目录与状态提示。
5. 历史保存在当前浏览器的 IndexedDB 中，每批记录包含对应目录句柄。刷新后仍可撤回；撤回只更新状态和时间，不删除历史。CSV / JSON 导出包含文件名，需妥善保管。

该功能会真实修改文件名，不是生成 ZIP 副本。目录权限和历史记录绑定浏览器与页面来源；清理站点数据可能丢失历史，不能把历史记录当作文件备份。

### 13.2 Auto Key 音乐调性识别

- **整曲分析**：导入一首或多首音频，查看主调、前三项候选、置信度、BPM、Camelot、色度和情绪估计。
- **调性时间轴**：导入单文件，选择 4 / 6 / 10 秒窗口，核对调性段落、波形和表格；点击段落可定位播放。离开页面会暂停播放并释放相关 Object URL。
- **实时监听**：选择麦克风或电脑声音，点击开始后按浏览器提示明确授权。电脑声音需选择支持音频共享的来源并勾选共享音频；离开 Auto Key、页面进入后台、`pagehide` 或手动停止会释放采集资源，返回后不会自动重新采集。

调性、BPM 与情绪均为算法估计，可能受编曲、转调、静音和音质影响，必须结合听感人工复核。受控浏览器验收使用合成 WAV、OPFS 测试目录和模拟采集流；真实麦克风、系统声音以及用户个人 Windows 文件夹授权仍需另行手动验收。
